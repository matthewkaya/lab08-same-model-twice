# PyTorch and Keras comparison

## Experimental setup

Both frameworks received the same 6,000 generated rows and prepared `float32` arrays: 3,600 training, 1,200 validation, and 1,200 test rows. `prepare.py` fitted numeric scaling and categorical encoding on training rows once. Each model used eight inputs, ReLU hidden layers `(128, 64)`, and one linear scalar output. The shared settings were mean squared error, Adam at `0.001`, batch size 64, up to 100 epochs, and seeds 2026, 2027, and 2028. Both ran on CPU. Each run selected its best checkpoint by validation loss and evaluated its test split once.

## Observed results

Values are mean ± sample standard deviation across the three seeds. Training seconds measure fitting and validation, excluding data generation and preparation.

| Framework | Validation MAE | Test MAE | Training time |
|---|---:|---:|---:|
| PyTorch | 2.6673 ± 0.1043 | 2.5825 ± 0.0900 | 7.57 ± 0.14 s |
| Keras | 2.7284 ± 0.0653 | 2.5792 ± 0.0853 | 21.93 ± 0.31 s |

Keras validation MAE averaged 2.29% higher, while its mean test MAE was 0.13% lower. Keras fitting took 189.56% longer, about 2.90 times the PyTorch mean. The saved Keras checkpoint measured about 136 KiB and is regenerated by `train_keras.py`; PyTorch `train_model` keeps its best state in memory. The PyTorch loop explicitly handles batches, gradients, and optimizer steps. Keras delegates these to `compile()`, `fit()`, and callbacks. That reduces training-loop code to maintain, while PyTorch exposes more points for custom per-batch debugging.

## Engineering recommendation

For this two-person team, I recommend PyTorch because possible Hugging Face integration is part of the scenario: the current [Transformers installation guide](https://huggingface.co/docs/transformers/v5.24.0/installation) documents a PyTorch-focused runtime. This experiment does not show PyTorch is universally better, and the project’s PyTorch 2.15 pin would need review before adopting that Transformers release. The tradeoff is maintaining the explicit training loop and its detailed control. If pretrained-model integration is dropped and the weekly job remains this small tabular fit, I would switch the recommendation to Keras; its `fit()` and callbacks suit a standard weekly training workflow and the teammate already knows Keras. Within each framework, resetting a seed reproduces initialization, but Keras Glorot and PyTorch Linear initializers and their shuffle algorithms differ, so equal numeric seeds do not create equal starting weights or batch orders.
